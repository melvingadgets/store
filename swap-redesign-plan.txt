SWAP PAGE REDESIGN PLAN — GATED LAUNCH
=======================================


CONTEXT
-------
The app is launching in phases:
  Phase 1: Users only see a standalone swap/trade-in tool behind a minimal
           branded shell. No other pages are accessible.
  Phase 2: Flip a flag and open the full e-commerce experience.

This plan builds the new /swap page and the gating mechanism.
The old swap page (/product/:id/swap) stays intact for Phase 2.


HOW THE FEATURE FLAG WORKS
--------------------------
Flag ON (Phase 1 — swap-only mode):
  - The entire app shows ONLY the /swap page
  - ALL other routes (home, products, cart, login, admin, etc.) redirect to /swap
  - Minimal app shell: header with store logo/name, no nav links
  - The old swap page still exists in code but is unreachable

Flag OFF (Phase 2 — full e-commerce):
  - Full app works normally — all routes, full nav, full footer
  - "Swap old device" button on ProductDetails goes to old /product/:id/swap
  - The new /swap page is NOT registered — it does not exist in the route tree

STEP 3: WhatsApp message utility
----------------------------------
- CREATE src/utils/swapMessage.ts
  buildSwapWhatsAppUrl(phoneNumber, params) returns a wa.me URL with
  pre-filled message containing:
    - Target device name, capacity, price
    - Trade-in device model, storage, all 5 conditions
    - Estimated trade-in credit range
    - Estimated balance to pay range
  Uses the existing formatPrice utility.


STEP 4: Build sub-components
------------------------------
All new files under src/component/swap/:

1. SwapProductCarousel.tsx
   - Swiper horizontal carousel of product cards
   - Tap to select, visual highlight on selected card
   - Fetches products using useGetProductsQuery()

2. SwapCapacityPicker.tsx
   - Appears after user selects a product
   - Capacity pill buttons (128GB, 256GB, etc.)
   - Shows selected product summary

3. SwapTradeInForm.tsx
   - Model dropdown + storage pills + condition assessment
   - Same UI as current SwapDevice.tsx trade-in section

4. SwapEstimateCard.tsx
   - Live estimate: balance to pay, trade-in credit
   - CTA: "Continue on WhatsApp"

5. SwapWhatsAppSheet.tsx
   - Bottom sheet overlay with message preview
   - "Open WhatsApp" and "Copy message" buttons


STEP 5: Assemble SwapPage.tsx
-------------------------------
- CREATE src/pages/SwapPage.tsx

  Composes all sub-components. Local state only (no Redux for form data).
  Uses existing RTK Query hooks for products, swap metadata, and evaluation.
  Supports optional ?productId=<id>&capacity=<cap> URL params.
  Integrates with AI assistant tradeInDraft auto-fill.

  Page layout (top to bottom):
    1. Header — "Trade-in Estimate" title
    2. SwapProductCarousel — pick device to buy
    3. SwapCapacityPicker — pick storage (appears after product selection)
    4. SwapTradeInForm — trade-in device + conditions
    5. SwapEstimateCard — live estimate + WhatsApp CTA
    6. SwapWhatsAppSheet — overlay when CTA clicked


STEP 6: Create minimal app shell for swap-only mode
-----------------------------------------------------
- CREATE src/layout/SwapShell.tsx

  Minimal layout for Phase 1:
    - Header with store logo/name only
    - No navigation links
    - No footer
    - Renders <Outlet /> for the swap page content


STEP 7: Gated routing
-----------------------
- MODIFY src/routes/AllRoutes.tsx

  The router checks the feature flag and returns a different route tree:

  When flag is ON (swap-only mode):
    - Root layout: SwapShell (minimal branded header)
    - Only route: /swap -> SwapPage
    - Catch-all * -> redirects to /swap
    - No other pages registered at all

  When flag is OFF (full e-commerce):
    - Everything works as today (unchanged)
    - The new /swap route is NOT registered — completely invisible
    - ProductDetails "Swap old device" points to old /product/:id/swap
